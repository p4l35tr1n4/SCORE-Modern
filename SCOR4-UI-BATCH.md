# SCOR4 interface completion batch

Start from Core 0.3.60 private build #1972. Use the supplied SCOR4 executable as the live reference, the SCORE 4 manual and both release notes as a workflow inventory, and Tom’s Help for SCORE command and parameter guidance. Verify the executable’s version at startup before attributing an observed behavior to 4.00 or 4.01. Keep the existing SCORE 3.11 profile as the default. MIDI playback is outside this batch.

## 0. Establish the reference and inventory

- Set up an isolated DOSBox-X copy with the supplied executable and verified local SCORE resources. Record the visible version, display mode, preferences, and test inputs.
- Capture the reachable menu banks as a table. For each box, record the context, row, label, enabled state, key, mouse action, destination, help, and equivalent typed command where established. Include both directions of bank traversal and Escape transitions.
- Give every reachable action a disposition: existing Core command, SCOR4-specific interface behavior, SCOR4-specific score operation that needs verification, or MIDI playback. Record how it was verified.

## 1. Complete menu dispatch and navigation

- Replace the preview Main, File, and Screen mappings with the observed labels, order, contextual help, and transitions. Add the remaining main banks and submenus.
- Verify F1–F10, Alt+F1–F10, and mouse activation separately. In particular, compare F9/F10 routing against Core’s navigation shortcuts and settle the Alt+F4 collision with the Windows close shortcut.
- Compare menu state on entering and leaving a prompt, cancelling an operation, switching profiles, and returning from Help. Keep Compact bottom menu selectable across both profiles.

## 2. Complete the file and command workflows

- Verify directory ordering, recognized files, numeric and mouse selection, refresh after save/delete, previous/next file behavior at boundaries, and the documented startup directory switches.
- Wire open, save, save variants, append, path changes, restart, command-file reading, and other verified File-bank actions to Core. Compare prompts, cancellation behavior, and which document remains active after each operation.
- Verify the SCOR4 distinction between copying to the cut buffer and deleting score items. Cover Cut, Paste, Undo, and Undelete through their menu entries.

## 3. Complete viewport and mouse behavior

- Verify Screen menu actions and keyboard pan/zoom, then compare page boundaries, zoom anchors, middle-button behavior with each `MOUSE` setting, and screen dragging.
- Verify item hit testing and the difference between moving the page and moving an item. Cover item reveal and AutoZoom, modifiers, cancellation, and clicking outside the page.
- Check interaction with Core’s native and DOS views. Confirm that switching the interface profile preserves the open score and applies the correct controls.

## 4. Complete input, item edit, and group menus

- Capture and wire all non-playback menu banks used by input, text, print, item editing, and group editing. Include context-sensitive boxes for notes, beams, slurs, and the remaining item types.
- Verify parameter selection, arrow and half-step moves, increment controls, mark movement, staff movement, and repeat-last-command. Use the 4.01 release notes to identify actions missing from the 4.00 manual.
- Verify conditional editing and other new commands that the interface exposes. Compare complete item records and changed record counts. Keep any required notation or processing differences isolated from the SCORE 3.11 command paths.
- Compare the supplied JUST4, PAGE4, DRAW4 and SCORLAS4 executables against the corresponding Core workflows, focusing first on the documented PAGE4 part-transposition correction and JUST4 fixes. Replace an entry in the non-page context menu for SCOR4 only where a verified difference requires a separate implementation.

## Final. Verify and package

- Run identical open → input → edit → pan/zoom → save workflows in DOS SCOR4 and the Core preview. Check screen state and saved records separately. Include cancellation and profile switching.
- Check the inventory for every reachable non-playback box. A disabled box or an unverified mapping stays open in the inventory. Record the specific evidence or dependency still needed.
- Run Core regressions in the default SCORE 3.11 profile. Verify the SCOR4 profile at ordinary and 175% Windows scaling, including compact menu height, contextual help, and access to Preferences.
- Produce a private Core build with the next cumulative build number and report the tested executable version, implemented behavior, remaining limits, and any documented SCOR4 processing differences outside the interface scope.

## After the interface batch

- Port the external TMB utility integration from ScoreModernX to Core. Compare the preference fields, context menu, arguments, producer identity and save/reload workflow against the existing fork. Exercise test utility runs in isolated copies.
- Compare SCORE 4 Help with SCORE 3.11 Help. Add clearly labelled Core Help sections for documented differences and check the affected topics against the live reference. Keep MIDI playback outside this batch.
- Reorganise Preferences around shared Windows settings and separate SCORE 3.11 and SCOR4 settings. Explain which controls apply to each profile, which values are inherited, and what changes when switching. Verify that both libraries and their overrides persist independently, controls remain legible at 175%, and the existing shared dialog choices apply in both profiles.
